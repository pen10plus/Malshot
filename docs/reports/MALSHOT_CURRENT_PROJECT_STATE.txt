SECURITY STATE
--------------

Resolved or materially mitigated:

1. Cache bypass through same-size/same-mtime file replacement
   - Clean-cache acceptance now validates the current file SHA-256 digest
     against the stored cache hash.
   - A regression test confirms replacement content is not accepted as clean.

2. Hardcoded quarantine encryption key
   - The compiled fixed key was removed.
   - A random 32-byte per-installation key is generated and stored with
     restrictive permissions under the vault.
   - Concurrent key initialization is synchronized.

3. Quarantine memory exhaustion
   - Quarantine no longer loads the whole file with os.ReadFile.
   - Data is processed in bounded 1 MiB chunks.
   - Each encrypted chunk receives a fresh cryptographically random nonce.

4. Quarantine path traversal
   - Source paths are cleaned.
   - Vault output is generated only beneath an absolute vault root.
   - Destination containment is checked.
   - A regression test confirms ../ input cannot create an outside-vault
     payload.

5. SQLite worker contention
   - Database connection pools are bounded.
   - SQLite busy timeout and WAL configuration remain enabled.
   - Eight concurrent cache writers are covered by a regression test.

6. ONNX native lifecycle
   - Session state tracks closure.
   - Inference and destruction are serialized.
   - Session state is removed from the global map during destruction.
   - Initialization failures clean up allocated tensors.

7. Scan shutdown safety
   - Active scans can be cancelled during engine shutdown.
   - Database closure waits for scan completion before closing connections.

8. UI stale event handling
   - Scan generation tokens prevent events from an earlier scan from
     updating a later scan's UI.
   - Threat counters now use consistent fallback handling.
   - Quarantine database reads occur asynchronously instead of directly in
     the Fyne list callbacks.

CURRENT TEST-CASE STATUS
------------------------

TC-SEC-01 - Path Traversal in Quarantine
Status: PASS
Path cleaning and vault-root checks are implemented and regression-tested.

TC-SEC-02 - AES Nonce Collision
Status: PASS at implementation level
crypto/rand is used for fresh nonces, including per encrypted chunk. A
large-scale collision test and native release test should still be run in CI.

TC-PERF-01 - Large File / RAM Exhaustion
Status: PASS for the remediation design
Hashing is streaming and quarantine encryption is bounded to 1 MiB chunks.
A real multi-gigabyte load test has not been run in the current environment.

TC-CONC-01 - Database Lock Under Load
Status: PASS
Connection pools are bounded and eight concurrent write operations pass.
Long-duration production load testing is still recommended.

TC-UI-01 - Rapid Scan Restart
Status: PASS by implementation and unit coverage
The engine prevents overlapping scans, coordinates cancellation, and the UI
filters stale events by scan generation.

TC-ERR-01 - Missing Engine Assets
Status: PASS for explicit initialization failure behavior
Missing or invalid engine assets return errors rather than silent success.
The complete YARA/ONNX runtime behavior remains blocked by the unavailable
native build environment.
